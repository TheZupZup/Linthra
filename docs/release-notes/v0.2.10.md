# Linthra v0.2.10

Linthra 0.2.10 makes remote playback faster, targets Android 17, adds a few library and Android Auto features, and carries another large round of stability fixes across playback, downloads, the offline cache, syncing and local libraries.

## Highlights

### Faster remote playback

- A remote track checks the session and fetches its stream URL at the same time, so playback starts one round trip sooner.
- A request lost to a brief drop (a Wi-Fi/mobile handover, a server restarting) is tried once more before the track fails.
- The next track's stream is warmed again near the end of the current one, so tracks change without waiting on the server.

### Android 17

Linthra now targets Android 17 (API 37). Android 17 blocks connections to the local network until an app is allowed to make them, so:

- Linthra asks for local network access when you test, sign in to, connect to or play from a server on your LAN. Background work never shows the prompt.
- Settings > Connections shows a "Local network access" card while a configured LAN server needs it.
- A server reached over a VPN (Tailscale, WireGuard and similar) can still connect without the permission.
- Playback still resumes after a call with the screen off, which Android 17 would otherwise block.
- A Play or skip sent from a Jellyfin remote on another device no longer starts playback while Linthra is paused in the background. Pause, stop, seek and control of playback that is already running work as before.

Local music and downloads never need the permission, and nothing asks for it on Android 16 or older. The minimum Android version is unchanged.

### New in the library

- Sort the Songs tab by title, artist, album or date added, in either direction.
- In the A-Z list, accented titles file under their letter, and titles starting with a digit or a non-Latin letter share one # section at the top.
- Swipe a song to the right to add it to the queue (Android).
- Open an album's artist from the album page.
- Android Auto has favorite and shuffle controls.
- Shuffle buttons start from a random song instead of the collection's first one, and adding songs to an empty queue with shuffle on shuffles them.
- Saving the queue as a playlist no longer duplicates songs.
- Settings keeps its categories in a sidebar beside the page on wide windows.
- Subsonic has an opt-in legacy sign-in for servers that refuse token sign-in, such as Nextcloud Music. It only works over https and keeps the password in the system's secure storage until you sign out. An app password or API key is the better choice where the server offers one.

### Linux desktop

- Starting playback keeps you in the list you were browsing. Now Playing is one click away, and Escape leaves it.
- Track rows show each song's length, album pages number their songs, and the queue opens as a side sheet on narrower windows.
- An opt-in "Show audio quality" switch (Music & playback) shows the codec, sample rate, bitrate and bit depth on Now Playing.
- The library catalog moves out of `~/Documents` into Linthra's own data directory. In the Flatpak this stops the library being rebuilt from scratch on every launch.
- A track that plays through a system sleep is reloaded after wake.
- Bug reports and diagnostics are saved through the desktop's save dialog, which also works in the Flatpak.
- Flatpak: with "Keep playing" on, Linthra asks the Background portal before playing on with the window closed, and quits normally if the desktop says no.
- Metered-connection settings use desktop wording instead of talking about mobile data.

## Stability

Most of this release is reliability work again. Nearly every fix comes with a regression test that reproduces the failure first.

### Playback

- A reload that loses its stream while seeking back, a seek on Android after a playback error, and a stream that failed during a call no longer hang.
- A stall after pressing Play on a paused track, or after a seek while paused, is caught instead of staying on Buffering.
- A copy that opens and then fails falls back to the cached file or another copy of the song, at the same spot.
- A seek on the error panel is where Retry and Play pick the song up.
- A mid-stream drop gets its quick reconnect back after real playback, so a later drop on the same track is still recovered.
- A playback failure can be explained and copied for a bug report.

### Downloads and offline cache

- Downloads are written to disk as they arrive instead of being held in memory, and one larger than the cache limit stops early.
- A body that ends short, an empty or truncated cache file, or an error page is never served as a downloaded song.
- An unreadable downloads record is set aside instead of being written over, so the next launch can't delete the files it named.
- Clear all and Remove download only ever delete inside the offline folder.
- Clearing storage stops a running "Download all".
- Cancel, eviction and removal no longer leave a song stuck on Downloading or marked downloaded with no file.
- Subsonic and Navidrome offline copies are tied to the server they came from.
- The artwork cache keeps covers per server, refreshes covers older than 30 days, never keeps an error page as a cover, and is capped at 256 MB.
- A custom cache limit such as `NaN` or `1e999` is refused instead of breaking the dialog.

### Sync and accounts

- Signing in to a different Jellyfin or Subsonic account replaces the previous account's library and queue instead of leaving its songs behind.
- Jellyfin and Plex no longer miss tracks when the library changes between pages. Subsonic goes on past an album that keeps failing, and reads one-entry lists from older servers.
- Large synced playlists save: Jellyfin adds songs 100 at a time, and Subsonic uses a form POST when the server supports it.
- Audiobookshelf renews an expired access token instead of failing every request, and servers older than 2.26 can sign in.
- A favorite or playlist change the disk refuses is undone instead of staying in memory, and a heart that wasn't pushed yet survives a restart.
- A Jellyfin answer without items no longer clears favorites or playlists.
- Plex reads numeric fields sent as strings, and treats a timeout or rate limit as a server error instead of a wrong address.

### Local libraries

- A music folder that is an unmounted mount point keeps its music instead of being read as emptied.
- A network share that stops answering no longer freezes rescans or the Local music card.
- On Linux, a FLAC, MP3, OGG or Opus file with one malformed tag field keeps the rest of its tags.
- A moved local song keeps its playlists, and a move that one store couldn't save is retried on the next scan.
- One malformed download, play history, playlist or saved-queue record now drops only itself instead of failing the whole load, and a failed read no longer clears the saved queue.

## Privacy

- Diagnostics and "Report a bug" describe server addresses (http or https, the kind of network, default or custom port) instead of including the host.
- Revealed password fields keep keyboard suggestions and autocorrect off.
- Cover URLs that carry credentials are kept out of the saved queue, the media session and MPRIS.
- Casting stays unavailable while #575 is open.

No telemetry, tracking or analytics were added.

## Accessibility

- The A-Z index letters are buttons a screen reader and keyboard can use.
- Buffering, the selected icon and section headings are announced.
- On desktop, Tab moves through one pane at a time.

## Upgrade notes

No manual migration is needed.

- Linux: the library catalog is moved from `~/Documents` to Linthra's data directory on first launch. If the move can't finish, the old file stays where it was and is used.
- Subsonic, Plex and Jellyfin covers are downloaded once more under their new per-server names. The old files age out of the cache.
- The first Plex sync after the update rebuilds the library once.

## Known limitations

- Android 17: a server whose only address is a global IPv6 address on the same subnet isn't recognized as local, so Linthra won't ask for access and the connection fails. Granting local network access in Android settings fixes it.
- Android 17: a VPN is recognized by its interface name (`tun`, `wg`, `ipsec`, `ppp`).
- "Show audio quality" is Linux only for now.
- Casting remains unavailable (#575).
