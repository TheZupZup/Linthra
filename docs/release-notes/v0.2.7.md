# Linthra v0.2.7

Linthra 0.2.7 is a large Android and Linux quality release. It fixes the Android Auto track-change regression reported in 0.2.6, makes the Linux local-library experience much more resilient, expands the desktop UI, and turns the GitHub Linux release into something users can install as a standalone Flatpak bundle.

This release is cut from the current `main` work rather than waiting for the remaining feature PRs. Those continue toward the next release.

## Highlights

### Android Auto

- **Next and Previous work again in Android Auto.** The media-session path now carries car controls all the way through Linthra's shared playback controller instead of letting the command disappear before the queue changes.
- The regression coverage includes playing and paused states, reconnects, queue boundaries, shuffle/repeat interactions and exactly-once dispatch, so one steering-wheel/head-unit press cannot accidentally skip twice.
- Track metadata remains synchronized after a car-originated track change.

### Android and accessibility

- Local Android metadata now reads **disc numbers**, including common values such as `1` and `1/2`, so the data needed for proper multi-disc ordering is preserved.
- TalkBack/accessibility semantics were audited and tightened across the main app surfaces, especially icon-only and stateful controls.
- Selection mode keeps its scroll position instead of jumping a large library back to the top.

### Local music on Linux

The local-library path received a substantial reliability pass:

- **Multiple music folders** can make up one local library.
- Linthra can **watch configured folders** and refresh automatically when files change.
- Incremental scans avoid reparsing files that did not change.
- Moved and deleted tracks are handled without treating every scan as a brand-new library.
- A removable USB/SSD music library is kept when the drive is temporarily unplugged instead of being mistaken for deleted data.
- Missing folders, permission errors and temporarily unavailable mounts now produce a recoverable state instead of silently looking like an empty library.
- Embedded local cover art is extracted and cached, with follow-up fixes for scaling and cache invalidation.
- The **Add folder** action now lives in **Folders**, where local-library management belongs, instead of the Library browsing header.

### Desktop experience

Linthra's Linux UI is much closer to a first-class desktop player:

- A persistent **queue side panel** can stay beside the main content on wide windows.
- Queue items can be reordered with mouse or keyboard.
- Playlists can be reordered and tracks can be dragged onto playlists.
- A global **quick search** overlay is available from the desktop.
- Compact and Comfortable density modes are available.
- The Now Playing bar/view, panes, hover states, context menus and multi-select behavior received a large desktop polish pass.
- Full keyboard navigation was added, followed by **configurable keyboard shortcuts**.
- Mouse-wheel and trackpad behavior was tuned for desktop use.
- Configured self-hosted sources can show their current availability state in the sidebar.
- Optional desktop notifications can announce real track changes without exposing provider credentials or private paths.

### Playback and audio on Linux

- Linthra can select the Linux audio output device.
- Audio-device hotplug is handled cleanly when devices appear or disappear.
- A broken/missing libmpv runtime is reported as a Linux runtime problem instead of being mislabeled as an ordinary track failure.
- A failed track now has a shared recovery path for retry, skip and provider fallback where available.
- Native playback diagnostics can be copied from Settings for troubleshooting.
- Playback work that was being performed unnecessarily in the background was reduced.

### Library, queue and downloads

- Entire albums and playlists can be downloaded for offline use.
- Search now folds accents more consistently.
- Recently played history is available in the desktop queue pane and received follow-up correctness fixes.
- Queue operations and desktop interactions received additional regression coverage for large libraries and long-running sessions.

### Audiobookshelf groundwork

- Linthra can connect to an Audiobookshelf server from Settings.
- The initial browse/library foundation is present.
- This is groundwork only; it should not be read as a claim that the complete Audiobookshelf playback experience is finished.

### Linux packaging

- Stable GitHub releases can now publish a **standalone `.flatpak` bundle** in addition to the native Linux archive.
- Flatpak audio and selected-folder library smokes run inside the packaged sandbox.
- Smoke cleanup was hardened so local contributor app data is not removed by destructive test cleanup.
- Flatpak permissions have written rationale and automated checks.
- The Flathub linter is part of the packaging checks.
- For this release, the Flatpak build moves to **GNOME Platform 51 / freedesktop-sdk 26.08** and the matching LLVM 22 SDK extension.

Linthra is **not on Flathub yet**. The standalone Flatpak is a GitHub Release artifact.

## Privacy and project guardrails

- The repository now has an independently runnable dependency-level audit for known advertising, analytics, attribution, telemetry and third-party crash-reporting SDKs.
- The current expected result remains: no known advertising, analytics, attribution, telemetry/session-replay/APM or automatic third-party crash-reporting SDK is present in the shipped dependency graph.
- This is deliberately a narrow claim: it does not replace review of Linthra's own network behavior.

## Casting

Casting remains **temporarily unavailable in production** while the receiver-trust remediation tracked in #575 is still under review.

Several Cast hardening pieces landed after 0.2.6, including receiver pinning/remembering groundwork and additional containment verification, but this release does **not** restore production Cast. There is no insecure fallback or user-facing bypass.

## Licensing

Linthra's **current project license is AGPL-3.0-or-later**.

The license transition happened after v0.2.4:

- releases through **v0.2.4** remain under the MPL-2.0 terms under which they were published;
- **v0.2.5 and later**, including v0.2.7, are released under **AGPL-3.0-or-later**.

The Linthra repository metadata, AppStream metadata and the F-Droid metadata kept in this repository all declare `AGPL-3.0-or-later`. Historical MPL-2.0 text remains preserved for the releases to which it applies.

F-Droid's separate canonical `fdroiddata` entry and some third-party listings may still show MPL-2.0 until their metadata is updated or refreshed; that synchronization is tracked in #659. That lag does not change the license of this release.

## Linux artifacts

The stable GitHub Release is expected to publish:

- the native Linux x64 archive;
- the standalone Flatpak bundle;
- the signed Android APK/AAB artifacts handled by the release workflow.

The Flatpak bundle targets GNOME Platform 51. Installing the bundle can fetch that runtime from Flathub when it is not already present.

## Upgrade notes

No manual data migration is required.

Your configured libraries, queue, downloads, server sessions and playback settings are intended to remain in place across the update. Temporarily unavailable local folders/drives are preserved rather than treated as deleted.
